## 3. Skills执行（强制）

### A. Skills Discovery

发现前端状态、数据建模、数据质量、迁移/测试/代码审查能力；优先确有事务与浏览器存储方法的技能。 检查当前AGENTS、宿主目录、实际配置和相关SKILL.md。当前会话与旧报告的目录不同；不得假设技能已安装或有统一调用语法。

### B. Skills Selection

数据质量技能检查唯一性/版本/血缘；真实工程技能处理IndexedDB和兼容迁移。不要把统计建模或安全扫描当通用存储技能；无匹配则用现有工程实践。 记录选用依据、范围、成本；每项选择必须与本包产物直接相关。

### C. Skills Execution

先写旧状态样本与失败注入，再实现追加、事务、幂等、保留旧key；暴露事件必须先于帮助显示，失败时给降级并标exposure_unknown。 在行动前读所选技能完整说明及相关配套文件，按真实流程实际操作。不得只列名字，不得为用技能增加无关工作。

### D. Skills Collaboration

内容作者定义evidence_requirement；工程负责attempt不可变和缓存重建；产品审阅状态文案是否暗示永久掌握；与ED03约定提交/求助事件。 可并行的任务明确输入、输出与文件所有者；共享合同修改先通知其他任务。

### E. Skills Validation

在docs/skills/executions/ED02.md简要列计划/实际技能、读取来源、采用方法、产出文件、验证及不可用原因。每项“使用”都必须有动作和产物；缺失技能采用常规方法并记录，不中断本包。必要时更新库存和矩阵，保留旧记录。

## 4. 具体实施步骤

1. 实现LearnerRepository，采用单一IndexedDB库，封装库选型可作简短ADR，加入必要stores；经济运行仍在SQLite，不复制全部事件。
2. 实现LearningAttempt与exposure记录；选项ID、item/version/variant/family、首次/重复/辅助独立、评估器版本可追溯；正式修改答案追加记录。
3. 实现LearnerEvidence派生函数，主状态not_attempted/practicing/independent_evidence；迁移和到期分开；后续错误保留旧证据并标需练。
4. 迁移FieldStudy/AuctionStudy：验证旧JSON、备份、事务、迁移收据、摘要幂等；旧first/latest标暴露未知，绝不补造掌握。
5. 导入导出按ID去重且检测同ID不同内容；运行缺失保留文字并标待恢复；存储配额/禁用错误可见，原key不删。
6. 把拍卖一个已有数值活动接入新记录，提供可查看尝试和来源的最小UI，避免只交存储层。
