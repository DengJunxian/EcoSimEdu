# ADR-001｜渐进课堂、运行证据与学习档案

状态为本工作包记录的架构决策。审阅锚点为 `8fc89711edb6a43e79e8b808ffb245edfdfe127b`。实施、兼容验证和阶段切换由后续工作包完成。[基线发现](baseline-audit.md) · [逐项回归门槛](acceptance-matrix.md)

## 主入口与迁移

`frontend/` 承担学生主入口和新四阶课堂。复用其 Case Map、`Lesson` 状态机、Studio、图表表格、续学和解释入口。继续使用暖纸白与森林绿和现有键盘模式。以可完成一条学生任务作为视图迁移单位，预测、行动、观察、解释、反事实和独立迁移各自有可验证产出。

`student-web/` 在迁移期间继续服务原 URL、七阶段教学、学生归档、复习、涌现索引、领域探究、参数台、模型实验和教师往返。先用明确链接接通高价值流程，再通过现有接口复用归档和领域能力。某个重复视图只能在替代入口、旧链接、记录和失败恢复全部通过后退出默认动线。历史 Run、事件号和原有分享链接继续可用。

维持模块化单体。浏览器规则的轻量执行和 FastAPI 本地实验能力各自保留。阶段内可以在同一进程下提供两套静态入口，具体路径由独立部署改造决定。只要站点来源变化，仍须为旧端来源保留访问或提供经实测的显式导出／导入。兼容测试涵盖已部署旧端地址和根 URL 的 query 语义。V2-00 不改变现有端口、执行方式和登录模型。

选择依据是已覆盖的两条运行路径。主入口已通过十二课独立静态执行，原端已有领域追踪和正式作答。维持两个完全独立的成品会持续重复路径与身份逻辑。整体重写会重做已经通过的原事件、提示暴露和归档恢复。渐进切换的代价是短期保留两套构建，以及维护可见的兼容入口。

## 仿真网关

按真实变化点设置网关，供课堂和证据界面调用。网关发布案例与模式的能力，执行或打开运行，读取可见帧与 Trace，生成或打开指定条件的对照。界面只接收本次可用的能力与已提交的结果。实际执行继续由现有浏览器内核和 FastAPI 接口负责。先接一个课的两种真实实现，从两者验证接口需求。

| 实现 | 从现有入口复用的行为 | 对调用方公开的事实 |
| --- | --- | --- |
| 浏览器规则 | `Lesson.run`、固定输入生成、`Recorder` 或旗舰帧、`run-evidence` | 当前种子与合法处理、运行版本、帧／子事件粒度、可见前缀及空值。支持基础离线。 |
| 本地服务 | `/api/runs` Create/Start、Manifest/Event/Export、Trace、Compare | 原 UUID、用原哈希检验的完整结果、原事件序与时钟、服务端完成或失败状态。 |
| 预计算 | 拍卖及精确匹配的预设读取 | 原始预计算来源和预设身份、实际种子及行动。 |
| 可选模型 | loopback 配置、原单角色、L2 与规则参考 | 只读模式可用性、既有授权与费用边界、执行状态、可辨别的完整结果／已提交前缀。 |

同一模拟请求的重新读取遵从现有运行幂等约定。可见回放暂停、运行取消及模型执行控制分别由对应能力决定。模型配置继续由本机服务处理，网关不持有凭据，常规学习路径在关闭在线选项时可完成。[现有创建与幂等](../../services/simulation/api.py#L414) · [本机配置](../../services/simulation/api.py#L301) · [L2 结果](../../services/simulation/live_l2.py#L413)

## CasePackage、Run 和 Trace

这些名称表达未来稳定的接口义务，沿用原格式实现适配。版本应由实际数据和兼容行为验证后定稿。

| 契约 | 所有权与关键字段 | 兼容与失效行为 |
| --- | --- | --- |
| CasePackage | `cases/catalog.json` 与 `case.json` 定义案例身份、正式资料和处理范围。v2 场景、v3 正式内容、概念及学习目标各自维持版本。四阶角色、展示指标与配对时钟由课堂适配器关联。整合时保留 caseId、case/content/schema/engine 版本、合法动作、指标单位、来源类别和能力。 | 旧 v2/v3 URL 响应保持原约定。新增清单只组合已有内容。历史事实／资料定位、实验材料、理论规则、合成开局、模型输出和假设按项目来源登记分别展示。 |
| Run | 固定运行身份、案例和引擎版本、提供者与来源、实际参数、种子、首次动作／预测引用、执行状态、经济时钟和原事件 ID。服务端 UUID 与准确结果摘要原样使用。给新的浏览器记录补可验证内容清单与结果摘要。 | 同一个运行 ID 在其原命名空间内保持身份。更改模型内容时，旧 ID 与旧版本留档。浏览器字符串 ID 保持适配，避免强转成 UUID。L2 的前缀摘要只核对前缀。 |
| Trace | 在明确 runRef 下读 `focus`、`asOf`、角色／观察者视角及经济时钟。节点或关系各有原始引用。配对差异、规则、恒等式、状态变化和解释假设保留各自口径。 | 继续返回现有服务端 SourceRef。浏览器原事件或子记录通过来源类型解析。图表位置独立于事件号，证据上限由查询及投影共同校验。来源版本不可重建时，显示具体状态并保留笔记及允许的原版入口。 |

校验粒度从案例 / 版本到运行，再到原事件或领域子事件。有效引用应能回到对应记录及其可见范围。跨引擎结果核对仅建立同条件的模型对照，两份运行各有 ID。原版 SQLite 与新浏览器生成的数据继续独立存放。将当前缺失值、未发生、未揭示、不可用与真实零作区分，展示时保持与原指标口径一致。

## 学习档案的数据所有权

| 数据 | 当前权威所有者 | V2 写入与读取原则 |
| --- | --- | --- |
| 运行与事件 | 旧格式 SQLite 或浏览器生成的版本化运行 | 原所有者验证运行身份。学习记录保存引用，缺少运行时保留文本与待恢复状态。 |
| 四阶续学及旧解释 | 当前浏览器来源的 `ecosimedu:progressive:*` 键 | 先增加检查点冲突判断与恢复状态。迁移使用显式源键和原值摘要，保留原值及版本。 |
| 正式作答、帮助、复习、活动、教师复核 | 原浏览器来源的 `ecosimedu-learning` 仓库 | 以原本地仓库和归档规则为权威。相同来源复用同一写入事务。需要换来源时使用用户发起的归档方式，完成后核对原引用和迁移收据。 |
| 原课堂进度、旧笔记 | 原来源的旧键和原运行库 | 继续由原解析器读取。历史完成状态与暴露未知按历史内容保留。 |
| 模型密钥 | 本机服务环境或进程会话 | 保持在服务端，排除出归档、运行内容、测试记录及跨来源交换。 |

首次预测、正式尝试、帮助暴露和教师复核追加保存。保存冲突时保留两份中有意义的内容，并显示待选择或明确的恢复路径。进度草稿允许主动回退。原 ID 去重按命名空间与记录身份处理，同 ID 内容冲突维持可审阅状态。个人、演示和教师导入记录保持原隔离。显示学习完成、独立证据和迁移结论各自的条件。

## 逐步实施与退出条件

1. 锁定入口、来源、版本及教学语义的回归测试。用原记录与本轮生成的测试档案验证备份可读。
2. 选择一个课程接入可见事件、对照行和原事件回查。两类运行都通过后，用已存在的通用视图承接同一用户路径。
3. 将学生主入口接到原复习、正式作答及教师流程，再推进课程内容整合。每次只迁移指定的产品切片。
4. 候选重复逻辑具有等价入口后，验证原深链、两套运行源、既有写入、失败恢复与离线操作。旧入口仍需按承诺提供历史读取。

V2-00 的决策给后续改造提供契约、兼容条件和可重复的证据。具体字段命名或批次遵照后续相应工作包。[迁移表](reuse-and-migration-map.md) · [验收矩阵](acceptance-matrix.md)
