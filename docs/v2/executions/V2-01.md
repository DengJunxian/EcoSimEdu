# V2-01｜统一学生应用入口

本包从 `codex/ecosimedu-v2` 的 `4d04e80b55481e4716c96c5fbd5de00218986044` 开始。本地工作树开工时干净。V2-00 的审阅锚点仍为 `8fc89711edb6a43e79e8b808ffb245edfdfe127b`。本包处理 B01、B09 的同源访问与跨来源备份，覆盖验收 A01、A03、A08、A10、A11、A12 的相关部分。

## 入口与数据

- FastAPI 在同一来源提供原 `/`、`/api/*`、`/learn/*`、`/cases/*`、`/emergence`、`/notes`、`/review`、`/teach` 和新增的 `/explore/`。`/explore?lesson=svb_run` 规范化为带斜线的路径，查询原样保留。返回旧四阶根查询书签时，原 `/?lesson=…` 和 `/?view=notes` 同源跳转到 `/explore/`。旧 `case/run/event/tick` 等组合仍走原实验室。查询深链和相对资产支持刷新。不存在的资产返回 404。旧包缺少四阶构建时在 `/explore/` 显示构建和返回入口，原实验室和 API 可访问。
- 两套构建共用品牌和路由定义。旧首页、原课程详情、实验笔记可打开对应四阶视图。四阶课程地图、课堂、实验笔记与原实验室之间使用同源链接。四阶课堂继续能用静态文件离线运行，所以原静态地址也可临时提供该构建以导出旧记录。
- 同源使用保留四阶 localStorage 键、原课堂键、`ecosimedu-learning` IndexedDB 和 SQLite 运行身份。新增四阶备份只携带已登记的进度与解释键。导入验证备份版本、键、案例与基本记录结构后写入，单次文件上限 5 MB。相同内容去重，目标同键不同内容保留目标值。存储失败按记录反馈并可重试，原键和备份文件可继续保留。
- 换过端口时，四阶记录从旧地址显式导出再导入。原作答用旧档案导入，七阶笔记用已有原始记录导入，较早通用课用旧课堂入口导入。运行链接依赖原 SQLite，以现有工具备份或继续使用原库。数据与系统权限均在本地操作。[学生指南](../../../STUDENT_LAB.md#换地址后恢复已有学习) · [四阶指南](../../../frontend/README.md#启动与验证)

## 本轮验证

使用锁定环境 Node 26.0.0、npm 11.12.1、Python 3.12.13 和 Playwright 1.65.2。手动验收服务与 pytest 夹具均使用临时运行数据库，真实学习源目录没有参与测试。

| 项目 | 本轮结果 |
| --- | --- |
| `npm --prefix frontend test` | 31 项通过。含原备份键、重复导入、同键冲突、格式失败及存储失败恢复。 |
| `npm --prefix frontend run build`、`npm --prefix student-web run build` | 两套 TypeScript 构建及 Vite、esbuild 通过。 |
| `python -m pytest -q tests/contracts tests/mechanisms tests/e2e` | 最终 459 项通过。契约与机制 342 项，三组互不重叠的浏览器回归分别为 30、32、55 项。回归环境隔离供应商凭据和外部开关。 |
| 统一入口专项 | `tests/e2e/test_unified_entry.py` 在 Chromium、WebKit 各通过 2 项。包括旧四阶书签到新入口、SVB 查询深链刷新与后退、原拍卖作答档案和 Run/事件 4、四阶跨端口导入及重开解释、两次导入幂等与原值保留。 |
| 两套学习入口 | Chromium、WebKit 使用同一地址分别跑课程地图、跨天续学、拍卖、SVB 和其余十课。覆盖 1180 和 390 像素；课程地图核对十二门旧课入口、笔记、复习及模型设置。离线教学通路限制为同源静态请求。 |
| 旧记录跨端口 | Chromium 在两个独立本地端口实跑原拍卖，导出并恢复 1 条真实作答记录和该课原始笔记。复核两端原笔记内容及同一 Run 的真实事件 4。两测试服务使用同一个隔离运行库。 |
| 本地包同时服务两套构建 | 用 `scripts.package_student_lab` 创建新包，独立解包校验，实际启动并请求深链和资源。新版归档的 620 个文件摘要与全部课程资产校验通过。临时移开解包后的四阶构建后再启动，旧页面、笔记和健康检查仍返回 200，四阶路径返回含恢复指引的 503。 |
| 静态资源与界面 | 两套共 76 个最终构建资产无凭据模式命中，渐进课堂构建无原硬编码端口。Impeccable 检测输出空数组。Chromium 在 320、390、1180 像素打开首页与备份表单，通过横向边界检查。 |

第一轮旧端回归发现历史通用课堂的 `Civitas Economica` 按钮兼作返回第一阶段，改名后影响旧备份恢复。保留原按钮名称和旧回放标题，两套首页共用 EcoSimEdu 品牌。第二轮发现新链接插入旧导航头部会改变 Tab 顺序；将渐进课堂入口放到兼容导航末尾，原通用课堂按原顺序直接进入“开始实验”。新页面测试发现 320 像素下原生文件控件横向超出 29 像素，限制表单列和文件控件宽度后复测通过。导航测试以「复习」标题和带尾斜线的正式路径核对。

## Skills 执行

| Skill | 实际动作 |
| --- | --- |
| Codebase Design | 核对 V2-00 的来源与路由决策，复用原服务、原数据所有者和恢复入口。跨前端共享的模块只包含品牌和路由，四阶备份复用已有记录解析。 |
| Impeccable | 使用 harden 与 craft floor 检视空态、错误反馈、键盘入口和文件上传在窄屏的边界。通过本机检测器与实际浏览器布局修正 320 像素溢出。 |
| Playwright | 使用仓库 Python 夹具及实际 Chromium、WebKit 复跑。逐个入口导航、检查 URL、前进后退、实际导出和文件导入、核对原 Run。用测试来源阻断外部访问。 |
| Diagnosing Bugs | 从全量回归的定位器失败复现旧按钮名称问题，恢复原控件合同后重跑。用元素边界定位窄屏溢出来源，修正同一控件并复测。 |
| Anti-Defensive Writing，两份本地说明 | 用实际入口、回归结果和数据所有权写说明，明确恢复条件及其检查边界。 |
