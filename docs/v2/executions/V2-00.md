## 定向复现

- **B03，真实 Chromium 双标签页。** 在同一临时档案打开双向拍卖，报价 96，选「不会成交」，进入第二阶。在打开的第二个同课标签保留事件 0。第一个标签单步两次，到事件 2。第二个标签仅单步一次。新标签从首页点「继续上次学习」，实际恢复到事件 1。全过程阻断静态来源之外的请求。测试新旧标签各自存储同一课堂的正常动作。
- **B02，受控版本变化。** 使用学校匹配固定种子和首个合法行动生成浏览器 Run，保留该 ID 及旧说明所指的第 1 个事件。内存探针替换这个帧的拒绝数，调用现有 `sourceRun`，它按相同 ID／帧号解析到了替换后的值。探针验证的是校验边界，正常的确定性复跑依旧满足当前契约。
- **B05，原序号与显示时点。** 同一次学校匹配运行分别查看 `lesson.policy.project(run)` 的行索引和对应首条事件 ID。输出 `0–0、1–2、2–11`。这验证了事件序号与显示索引需各自保留。
- **B04，SVB 数据粒度。** 运行已登记的 SVB 基准，取第一个包含 payment 的帧。第 1 轮含 `revaluation、request、payment`，`runRecords` 返回的索引种类只有 `round`。对照当前解释选择器和 JSON 导出，确认它以轮作为证据单位。

后三条探针由现有入口重现，命令从仓库根目录执行。

```js
// node --input-type=module，粘贴运行
import { lessons } from './frontend/tests/remaining_parity.mjs';
import { sourceRun } from './frontend/src/learning-store.ts';
import { runRecords } from './frontend/src/run-evidence.ts';
import { svbLesson } from './frontend/src/svb.ts';

const matching = lessons.find(lesson => lesson.id === 'school_matching');
const choices = [matching.decisions[0].options[0].id, 'prediction-0'];
const input = { seed: matching.seed, choices, policy: matching.policy.baseline };
const result = matching.run(input);
const note = { choices, baselineEvent: 1, baselineId: result.id };
const syntheticRevision = { ...matching, run: request => {
  const run = matching.run(request);
  return { ...run, frames: run.frames.map(frame => frame.tick === 1
    ? { ...frame, metrics: { ...frame.metrics, rejections: 999 } } : frame) };
}};
console.log(sourceRun(syntheticRevision, note, 'baseline').run.frames[1].metrics.rejections);
console.log(matching.policy.project(result).map(frame => [frame.tick, frame.events[0]?.id]));
const bank = svbLesson.run({
  seed: svbLesson.seed,
  choices: svbLesson.decisions.map(decision => decision.options[0].id),
  policy: svbLesson.policy.baseline,
});
const first = bank.frames.find(frame => frame.events.some(event => event.kind === 'payment'));
console.log(first.tick, [...new Set(first.events.map(event => event.kind))],
            [...new Set(runRecords(bank).map(record => record.event_type))]);
```

## Skills 的实际使用

| Skill | 动作与对应产物 |

| Codebase Design | 以两条已有执行路径定位真实接口变化，按调用方约束梳理网关、三份数据契约、替代入口与测试。写入 ADR 和迁移表。 |
| Playwright | 验证运行环境后复用仓库 Python 浏览器夹具。运行两个引擎的四阶脚本、旧端 WebKit 专项及双标签最小复现，并核对五张图实际渲染。 |

| Diagnosing Bugs | 用同一测试档案的两标签复现检查点倒退，用单用例复现与开关对照定位全量测试的环境差异。 |
| Analyze Data Quality | 以目录 ID、运行来源及事件粒度为核对单位。逐课核对 case/v2/v3，实际复算双内核、缺失值边界和来源资产，区分 SVB 的轮次与子事件。 |
| Anti-Defensive Writing，两份本地说明 | 用可复现结论组织审计及 ADR，保留影响结论的失效记录、环境差异、历史格式和测试边界。 |
