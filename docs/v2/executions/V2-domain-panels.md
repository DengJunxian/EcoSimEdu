# 四阶课堂的六门领域面板

本轮以 `48b0ad8` 为基线，先接入公共品、公地治理和碳配额，再接入啤酒游戏、GameStop 和闪电崩盘。第二、三阶的「经济世界」复用原七阶领域组件，按当前回放位置显示实际发生的记录。键盘定位其他事件后，焦点移到回放位置。第四阶沿用先预测后运行，在领域面板核对两组收尾账目，随后保存解释、回查来源和提交独立迁移。

## 逐课实走

各行使用相同种子与学生选择运行两组，只改变表中列出的制度条件。记录均由浏览器规则模型实际产生。迁移题为课程编写的新情境，测试作答来自自动化浏览器。

| 课程及种子 | 领域内核对的原事件 | 政策组对照 | 独立迁移 |
| --- | --- | --- | --- |
| 公共品 · 2000 | 首轮四笔贡献合计 29，人均公共回报 11.6。事件 2 的全组净收益为 97.4。回查事件 1 时结算仍未出现。由下一轮反馈可回查事件 2。 | 无惩罚 → 低成本惩罚，累计全组净收益 1019 → 949.6 代币。 | `pg-kitchen`，核对新情境中的净支出。 |
| 公地治理 · 2009 | 事件 1 记录取用 74，剩余 106。事件 2 记录再生与下期期初库存约 138.55。回查时保留所选使用者。 | 开放取用 → 每人每期最多 1 单位，期末资源 0 → 206.0646。 | `commons-aquifer`，识别地下水补给条件。 |
| 碳配额 · 2005 | 事件 2 转移 A0009 至 A0012，可从登记簿回查发行事件 0。事件 9 记录 F01 缴回 4 张。 | 发行 88 张 → 56 张，总减排成本 1318.5 → 3357 代币。 | `carbon-proportional`，检查配额总量是否随产量变动。 |
| 啤酒游戏 · 1989 | 零售第 5 周下单，批发第 6 周收到 8 件需求，同时收到 4 件实物。该物流批次链接到第 4 周发货事件。 | 各环节看本地订单 → 共享终端需求，工厂订单方差比 56.9861 → 36.4579。 | `beer-delivery`，区分实物库存和未到货订单。 |

业务事件、运行 ID 和归档校验摘要沿用原版本。原有记录字段保存其原始数值，面板快照补充实际账目和挂单档位。四阶公地模型只含取用与再生，管护账户在原七阶模型中保有独立记录。解释表单分别保存模型规则、算术核对、配对差异与现实假设。

## 复现

依照 [V2 启动指南](../release/README.md) 构建两端并启动本机服务。浏览器验收使用隔离档案，限制请求为课堂静态资源，关闭在线模型。用已安装的 Chrome、Playwright WebKit 和可选的本地 axe 文件复现。

```sh
npm --prefix frontend run build
npm --prefix student-web run build
npm --prefix frontend test
python -m pytest -q tests/contracts tests/mechanisms tests/e2e
python -m frontend.tests.auction_parity
python -m frontend.tests.svb_parity
python -m frontend.tests.remaining_parity
python frontend/tests/domain_panels_browser.py http://127.0.0.1:8776/explore chromium 390
python frontend/tests/domain_panels_browser.py http://127.0.0.1:8776/explore webkit 320
```
