# EcoSimEdu 第二轮产品审计：从完整实验课走向连续自主学习

- 审计日期：2026-11-18。
- 代码基线：`bfe31dd945eaff3cac7c92a580974ad1e3cd45e2`，仓库已合并上一轮 UP00–UP11。
- 本报告范围：源码、当前产品设计文档与学习状态合同；实际浏览器观察由主审报告补充。下列“存在”指已在当前源码中接通；不将历史测试收据替代本轮运行验收。
- 当前没有提供真实学生的行为日志、访谈或学习测量。本报告提出的使用负担和学习机会是有代码依据的产品判断，不是已经观测到的流失原因或教学效果结论。

## 1. 结论

这轮应保留已经形成的十二门实验课、差异化学科画面、七幕教学、真实运行与证据回查，把建设重点转向三个连续问题：**学生先学什么、完成后能做什么、下一次该怎样继续。**

现有产品已能让学生进入一课、选择行动、观察实验、比较条件、保存带证据的解释。跨课层面目前主要依靠目录分组和草稿续接。学习者的概念理解、误解、独立解题表现、迁移能力和复习需要还没有成为统一产品对象。继续增加模拟参数或页面数量，不能自动弥补这层缺口。

建议把本轮发布目标写为：**不配置 API 的学习者可以完成一条有先修关系的课程路径；获得可核对的能力证据；用另一情境检验解释；离开后按明确原因回到合适的复习或下一课。**

## 3. 高价值缺口与优先级

### P0：把“看过哪课”与“能够做什么”分开

**源码事实。** `FieldStudy` 记录 stage、unlocked、answers、evidence、comparisons、explanation 等；`AuctionStudy` 记录场景、答案与笔记。它们没有稳定的 competency ID、一次独立作答的 attempt、提示使用、复习安排或跨案例能力状态。新版首页按 updatedAt 排序续接最近草稿；最终笔记阶段仍是可续接草稿。旧版 complete 与新版场景进度并存。

**产品影响判断。** 系统能恢复位置，无法可靠回答“我已经能独立区分流动性与偿付能力吗”“我应再练一次还是进入闪电崩盘”。直接给学习者百分制掌握分会超出证据。

**升级。** 引入最小学习证据账本，不替换实验账本。记录任务版本、能力、回答、是否查看提示、反馈、相关运行引用及评估规则版本。对外采用“未尝试、练习中、有独立证据、待复习”的可解释状态。旧草稿迁移只证明活动发生，不能补造掌握证据。

**验收。** 同一课可显示“实验已完成，机制解释待验证”；有提示后的正确答案与首次独立答案保留区别；同一事件重复保存不提升状态；导入旧记录不凭空生成通过结果。

### P0：把四条静态分组发展成可执行学习路径

**源码事实。** `docs/curriculum/knowledge-map.json` 是四个路径和每课概念字符串；`PathsPage` 只是逐组列出课链接。`CasePage` 展示背景、行动、资料和边界，尚未展示 catalog 已有 goals 字段。

**升级。** 每课详情先呈现“学完你能做什么、需要什么、这一课会留下什么成果”。课程路径加入先修能力、推荐顺序、可跳过的入门检查、跨案例桥接任务和结课挑战。概念图作为展开视图；默认呈现下一项行动与原因。

**验收。** 12 课全部有目标—任务—证据映射；用户可看见推荐基于哪项先修或未完成任务；跳过诊断仍可学习；已有学习记录能够定位到路径节点。不得用案例数量或看完百分比冒充能力。

### P0：调整七幕节奏，围绕学习问题控制交互负担

**源码事实。** 通用课 `flagship-lesson.tsx:461–470` 要求运行结束后进入解释，所有情景运行后才进入笔记。拍卖课 `auction-lesson.tsx:413–425` 也要求收盘以及需求、费用两组反事实都运行。已有 checkpoint 自动暂停与预测回查，具有复用基础。

**升级。** 保留七幕组织，在 observe 阶段加入有依据的暂停提问：发现差异→定位主体→解释一步→继续预测。为每课设置“最低完成的必要任务”与“可选扩展”；基准加一项与本课目标对应的反事实即可形成有效初次闭环，第二项对照可进入深入任务。具体课程如目标必须比较两种制度，则在目标上明示并保留要求。

**验收。** 必要对照由 case package 声明，不由 renderer 硬编码所有 scenario；提前跳过解释任务不会获得能力通过，但不锁死后续探索；观看完整结果、答对选择题和写有文本分别记录，不能彼此替代。

### P1：把笔记由每课存档提升为解释能力的工作台

**源码事实。** 新笔记已核验引用，显示初次与最新回答、比较与记录，最后主要是 mechanism explanation 与 condition 自由文本；原事件的有效性不等于该事件支持写下的论断。

**升级。** 为每个解释卡组织 Claim（主张）、Evidence（证据）、Mechanism（机制链）、Boundary（边界）、Alternative（替代解释）。保留自由写作；提供可移除的句式支架。证据拖入或按钮添加后，要求学生说明它支持哪一步。将参数台和运行对照的特定观察点直接带回卡片。

**验收。** 引用失效明确标出；合法但不相关的证据不能仅凭存在自动给高分；规则能核验数值任务和引用身份，开放解释采用明确 rubric 与自评/示例对照，AI 仅提供可撤回建议，不作唯一裁判。课堂笔记和高级实验笔记共享引用合同。

### P1：建立自然的返回理由

**源码事实。** 首页最新草稿续接、NotesPage 案例记录均已具备；缺少基于能力证据的复习队列、延迟任务、跨案例下一课及理由。这里的缺口由状态合同和渲染判断，尚无真实次日留存资料。

**升级。** 首页在“继续上次”之外，仅显示一项建议复习和一项下一课。推荐采用透明规则：未完成关键任务→相关误解练习→到期回忆→具备先修的下一课→自主探索。允许忽略、更换目标、暂停复习，不引入连续打卡压力。

**验收。** 冷启动、已完成一课、需复习、内容升级、记录损坏、全部完成六类状态都有可执行下一步；推荐原因与本地记录一致；用户可重算、关闭或清除。离线仍工作。

### P1：让既有提示真正进入形成性反馈闭环

**源码事实。** 三级提示已存在；答题选项有反馈；主学习状态未记录提示等级与答题尝试序列。TutorPanel 当前请求与回复主要在组件 state，不能作为跨任务的学习证据。

**升级。** 错误诊断以内容作者定义的 misconception ID 为依据。提示一次只推进一个思考动作，优先返回现场查证；看过最终解释后仍要完成平行题才获得“独立证据”。解释任务与数值任务分开检查。

**验收。** 无 API 时，同样存在分层提示、误解反馈与下一道题；同一错误不会无限重复泛泛的“再看看”；助手不能替学生回填答案、提高掌握状态或修改原始运行。

### P2：整理既有入口，降低技术参数在初学路径中的显著性

**源码事实。** AppShell 主导航包含模型实验；案例详情与比较阶段链接参数对照。参数台优先呈现种子、学生行动、对照参数；其结果已经可回到原事件。

**升级。** 保留高级入口，但默认课内只呈现有目标的“换一个条件检验你的解释”。随机种子与哈希折叠为实验细节。高级台添加假设→操纵变量→预期指标→结果→解释的小实验卡，不强迫全部课程都进入开放参数界面。

**验收。** 新学生完成一条主路径不需要理解 provider、hash、token；高级用户仍能查看完整运行身份与复现参数。现有旧链接继续可用。

### P2：轻教师辅助沿用现有能力

**源码事实。** 教师模式、答案展示、预设导出主要在旧 LabTools 与旧 lesson 页面；当前新旗舰未直接接入这些工具。

**升级。** 为每课加入折叠教学说明：先修、典型误解、推荐暂停点、讨论问题、黑板机制图、10/20/40 分钟组合与可打印活动页。展示模式可隐藏答案和笔记个人信息。先把现有能力迁到新界面；不增加班级、评分和作业后台。

**验收。** 任一正式课可打开展示版并恢复学生模式；同一内容源生成学生课、教学提示和活动页，避免维护两套经济学结论。

## 4. 研发优先次序

1. 学习目标与任务证据合同；使用拍卖、SVB、Schelling 三课验证。
2. 可解释能力状态、一次作答记录、提示记录、内容迁移。
3. 任务式解释笔记与第一组跨案例迁移题。
4. 下一步推荐、复习与四条路径的真实导航。
5. 迁移剩余九课，并整合旧概念/教师能力。
6. 真实使用后再评价学习和回访；本轮不以更多 LLM 调用或案例数量作成功指标。

第一项发布增量应让一个学生从拍卖课独立完成“报价上限—个体成交—总剩余—交易费”的解释，再在一个未见过的小市场中复用概念。通过这一闭环后再横向铺开。

## 5. 明确不建议的本轮扩张

- 不重复重建首页、十二课场景、参数台或模型切换。
- 不以增加十几门新课优先于完成现有十二课的目标、任务和迁移。
- 不建设商业账户体系、教师机构后台或复杂 LMS。
- 不将有限正确题数包装成精确知识掌握概率；先采用透明状态与证据。
- 不用浏览时长、点击次数、代码测试数证明教学效果。
- 不让每一个提示依赖 API；基础模式继续完整。
- 不在缺少学生数据时宣称“主要流失点”“预计提升留存 X%”或“已验证学习效果”。
