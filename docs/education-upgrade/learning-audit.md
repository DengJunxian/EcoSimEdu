# EcoSimEdu：教育能力复审

审查日期：2026-11-18。固定代码基线：`bfe31dd945eaff3cac7c92a580974ad1e3cd45e2`。本报告只读审计，不修改产品。范围是 12 份 `lesson-v2.json`、12 份模型说明、知识路径、学习首页与案例导入、通用课堂与三旗舰练习、笔记及反馈组件。页面实测由总控另行记录；本报告的运行行为结论以可追踪源码为依据。

## 1. 结论：已有可用的课堂，下一步需要连续的自主学习系统

这次升级应当把重点放在「学生能否从一次解释走向独立判断、换题应用、跨课联系和之后的再次提取」。现有版本已经完成了许多上一轮应做的工作：独立首页与案例库、四条主题路径、12 个七阶段课堂、真实模型动作、领域专用视图、原预测与修订、可定位事件证据、同步对照、解释笔记，以及三个旗舰里的手算活动。继续以“所有课程都是三道一样的题”“只有文字加按钮”“缺少首页导航”“没有手算和反馈”作为整改理由，将与当前代码事实不符。

目前更实质的教育缺口有四个：

1. **课程目标还没有成为系统可用的能力与证据关系。** 目标写在场景文本里；知识图是主题分组和概念名列表；系统不知道哪个练习能支持哪项学习判断。
2. **好的局部教学动作没有形成统一的学习过程记录。** 角色预测、三旗舰的数值练习、概念题、证据笔记各有存储和反馈方式；无法稳定区分初次作答、提示后修正、看过答案后的重复、独立换题成功。
3. **从模型操作到经济学解释仍依赖学生自己补足。** 页面常要求“查一条记录”“核对一笔账”，这些是重要基础；还需组织出“哪个激励/信息/约束变化，经哪些互动，改变何种总体量”的解释步骤，以及区分竞争性解释的实验。
4. **跨课迁移和延后复习尚未成为可运行的产品功能。** 目前末页的迁移提示有价值，但多数停留在自由文本与自评；课程间没有针对共同概念的变式任务、下一步理由和复习入口。

这些判断指向一个增量升级：保留 12 课与模型资产，抽取学习证据协议，做深三个旗舰，再把通用能力推广到其余九课。没有必要以扩充案例数或实时 LLM 调用量作为本轮主要成果。

统计单位为 `lesson-v2.json` 中的 `questions`，不包括领域组件中已有的手算、地图点选、参数选择、证据引用和开放笔记。不能用这张表推出“课里只有选择题”，也不能把题数当教学质量分数。

另有 41 题带 selector，12 课各一条末页 rubric。62 道概念题均为二选一；56 道的正确项在第一位置，约 90.3%。渲染直接按原 `options.map` 顺序显示，不打乱。这个发现说明答案位置可能成为低成本猜题线索；没有学生作答数据，不能声称“学生已经在用它作弊”或推算实际猜题率。应稳定地按 attempt 打乱适宜选项，保存展示顺序；有自然排序的选项保持顺序，并通过题库编排消除位置模式。更重要的是加入解释、计算、证据选择与新情境判断，避免仅通过调整答案位置就宣称评价有效。

知识图包含 48 个概念字符串条目（每课 4 个），无稳定概念 ID、跨课去重/关联或先修边。它是现有内容索引，不是“知识图谱已建设完成”的证据。

## 4. 教学质量逐项判断

### 4.1 目标、活动和评价的一致性：内容层有基础，系统层未建立

优点很具体。拍卖目标“从一笔成交追到两张订单”对应真实订单；SVB“按 request_id 连申请、部分付款、余额”对应账本；Schelling 的局部比例、满意率和邻接率分母不同被明确教出。这些不是装饰性目标。

薄弱处是能力难以验证。例如 SVB 的目标要求“重算一帧现金和权益”，数值表单确实存在，但 `records` 储存的是一段反馈文字，不能表达题目版本、提示程度和独立成功。`SceneQuestion` 的 TypeScript 类型只含 prompt、kind、selector、options 文案；文件里的 `criterion` 并未成为统一评价接口。场景目标与题目之间也无机器可检查的映射。

建议把每课目标压成 3 项可观察成果：能计算/分类；能用事件解释传导；能设计对照并说明适用条件。每项至少对应一个真实活动和一个独立检查。维护一张“目标—活动—证据—反馈—迁移”表即可，不建设庞大教学管理系统。

### 4.2 误区与反馈：已针对学科，下一步是修正过程

已有高质量例子包括：借款增加现金但不增加权益；申请不等于实付；相同公开行动不等于独立信号；费用转移不等于资源消耗；稳定匹配不等于人人得到首选；相同末笔价格不等于相同路径；零阈值不会主动把地图混合。这些内容应保留。

当前反馈通常随点击立即全部显示，允许来回点选；概念题只有 first/latest。拍卖数值核对以一个布尔结果判断三项，错误时显示所有正确值，无法区分哪一步错；Schelling 练习状态为组件本地 `useState`；SVB 将作答和完整算式写到一个字符串。它们能教学，但不能直接作为“独立掌握”的统一证据。

升级要求：按具体错误给第一条过程提示，提供第二级带空格的算式，再允许查看完整解答；每级都可主动选择，不以反复失败惩罚用户。保存提示与解答曝光状态。解释过的原题再次答对属于“完成修正”，要换一个同构题才形成新的独立证据。

### 4.3 探究深度：给定对照已成立，设计对照还可深化

现有场景不只是播放按钮：学生能设一次有效行动，使用共同初态/种子比较制度，而且模型文档承认结果可能相同或非单调。这种可信性值得保留。

进一步应让学生决定：我在检验哪个假设？改变哪一项？保持哪几项？在什么时点比较什么指标？哪种结果会削弱我的解释？先给结构化选项，再开放短句。无需对初学者开放全部研究参数。12 课各增加一张“实验计划卡”，在高级自定义入口前复用已有 Scenario Provider，并针对不支持的组合明确限制。

不是每次动作都要变成强制测验。自由探索允许直接运行，界面标记“探索记录”；引导路径提供“先预测/先写依据”的学习支持，不把浏览权等同于答题通过。

### 4.4 从微观到总体：已有账本和事件，需补足机制概括

现有引导擅长“这笔记录有没有发生”。学生还需主动组织三种关系：

- **账户恒等关系**：实付使现金与负债同减；不能把恒等式本身叫因果识别。
- **模型规则与事件关系**：库存阈值触发撤单、邻居消息进入风险分；用实际事件与规则支持。
- **制度比较关系**：相同初态下调整规则造成的本模型差异；不能自动代表历史因果效应。

建议在解释笔记中明确 claim/evidence/reasoning/condition 四部分。证据核验继续复用现有 hash；推理质量用带锚点的自评量表与范例比较。离线检查可以检测缺引用、单位/时间口径、未完成对照；不应仅凭关键词自动判定开放解释正确。

### 4.5 数学支架：已有点状练习，欠缺按难度渐退

三个旗舰已有练习。其他课程有明确公式，但例如信息级联从“一张抽样卡”跳到个人/公共后验与行动似然，碳市场从“免费配额”跳到二次成本和离散边际成本，啤酒游戏引入库存位置与方差比，都需要可跳过的短桥梁。

建议五个通用微课：比例与分母；存量/流量/账户平衡；边际量与总量；概率与条件信息；单变量对照与不确定性。每个 2–4 分钟，带一个具象任务、一个完整例题、一个填空、一个新数值问题。高级学习者可以直接做独立题跳过，不强制重学。

### 4.6 迁移、间隔和下一步：目前最值得投入的缺口

末页已有“换到二手设备/实习岗位/真实水域需什么信息”等提示，不能说完全没有迁移设计。但它们大多是开放反思，不给对比情境、所需条件或参考判断。学生可以写“还需更多数据”而不真正辨认哪一条前提失效。

每课至少增加一个近迁移与一个远迁移/不适用辨认任务。近迁移保留机制改数值/主体；远迁移同时呈现相似处和关键差异，允许“目前不足以判断”。例如 SVB 到现金流紧张企业：现金时间错配类似，但存款随时可兑付、保险和银行监管的前提不同。不能把所有欠款都叫挤兑。

下一课推荐说明具体依据：“你已在银行账表中区分存量与流量，啤酒游戏会把这一能力用于库存和在途。”复习以本地到期任务呈现，延后重新提取机制或计算，不让用户只重看答案。具体复习间隔是可调整的产品规则，不应宣传为已验证最优的算法。

## 5. 本轮应验收什么

| 层面 | 可执行验收 | 不足以验收的替代指标 |
|---|---|---|
| 对齐 | 12 课各 3 项可观察目标，均映射活动、判断标准及迁移题 | 课程字数增加、目录页增加 |
| 练习 | 三旗舰已有组件接入版本化 attempt；至少一个新变式独立检查；提示后成功与独立成功分开 | 正确反馈出现、按钮能点击 |
| 解释 | 一条 claim 有真实事件证据、规则连接和边界；能看到示例与反例 | 引用 hash 有效即判断解释正确 |
| 迁移 | 每课一个近迁移与一个条件辨认/远迁移题，有参考解析；完成不依赖 LLM | 末页一句“还可以解释什么现象” |
| 复习 | 本地日期推进可验证复习到期；同义新题而非只重复原选项 | 连续签到、累计停留时长 |
| 推荐 | 每次给出最多三项下一步、具体理由、可跳过；不误锁进度 | 模型生成一句泛泛鼓励 |
| 质量 | 12 课学习证据结构通过验证；典型错误路径和无目标事件路径能完成 | 单纯增加 E2E 截图数 |

所有阈值都是产品验收，不是教育效果已经得到实验验证。此阶段无需建设班级、评分工作流、正式考试或进行真实教学实验；也不应据自动测试宣称“学习效果提升 X%”。

## 6. 实际 Skills 使用与研究边界

已读取真实可用 `data-analytics:analyze-data-quality` 及其 `analysis-quality`、`source-selection`、`metric-definitions`、`shared-skill-instructions` 参考。云路径的相对参考读取失败后，通过当前实际 executor 安装路径读取对应文件；没有安装新技能。其有效方法用于：先声明题目记录粒度、区分文本题与组件练习、检查字段与答案位置、追踪实际渲染绑定、以具体证据区分实现与教育推断。结构化结果保存在 `learning_content_profile.json`。

没有把该技能称作专业教学设计技能。教育设计由文献核查、目标对齐和真实代码阅读完成；当前可见技能目录不支持假定存在名为 instructional-design 的专用能力。学习研究资料与适用限制见 `research-sources-detail.json`。所有推荐仍需在实现时通过内容专家复核与真实可用性检查；本报告没有虚构学生研究或学习成效数据。
