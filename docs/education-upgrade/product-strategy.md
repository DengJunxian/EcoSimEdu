# EcoSimEdu 下一版本产品策略与可执行需求

> 方案性质：基于 2026-11-18 当前代码的产品决策建议；尚无真实学生队列数据。本文件与 `product-audit.md` 一起使用。课程理论与题目内容由独立教学审查补齐，不凭界面完成度推断学习效果。

## 1. 产品承诺与版本目标

**对学生的承诺：用一个真实或有学术依据的经济问题进入学习，亲自做决定，用实验记录解释机制，再证明自己能把它用到新问题上。**

上一轮已建立十二课的完整实验体验。本轮要交付一个能够连续使用的自主学习系统：从目标选择到诊断、实验、解释、迁移和复习都有明确下一步；学习成果可回看，推荐有理由，核心流程离线可完成。

### 最重要的产品决策

| 决策 | 选择 | 理由与代价 |
|---|---|---|
| 内容投入 | 先深化当前 12 课，再扩大正式案例数；候选案例保留研究资产状态 | 目标、题目、迁移与反馈的完整度高于新标题数量；短期课数增长较慢 |
| 主学习单位 | 一项可以展示证据的经济学能力 | 案例仍是入口，能力联结课程；需要统一 ID 与题目标注 |
| 进度 | 活动进度和能力证据并列 | 浏览、看完实验和独立掌握意义不同；界面需要清晰解释 |
| 推荐 | 小规模透明规则，学生可跳过 | 当前样本不足以支撑复杂学习者模型；规则可审查、可离线 |
| AI 角色 | 提示、追问、解释建议；规则与案例内容保证基础闭环 | 保持离线，防止 AI 替答或不实掌握判断；开放文本无法完全自动可靠评分 |
| 验证 | 任务可用性、经济机制、证据链、形成性评价分别验收 | 功能测试无法证明学习增益；不扩大为正式课堂实验 |
| 本轮工程边界 | 在既有 React/Python/Case Package 合同上增量扩展 | 当前基础已可复用；新状态层与旧记录迁移有真实成本 |

| 轻教师用户 | “在有限时间展示一个机制并组织讨论” | 旧教师模式、答案开关、预设导出 | 新版统一教学提示与暂停点；保留展示、打印和导出，不扩为 LMS |

### 成功的最小学习闭环

1. 学生能说出本次要解决的问题。
2. 在看到结果前作出可保存的预测或选择，也可明确“不确定”。
3. 对一个有经济含义的条件采取行动。
4. 找到相关个体与集体结果的记录。
5. 写出有证据、机制和边界的解释。
6. 用一项未见过的相近情境任务检验理解。
7. 离开时知道下一次行动及其原因。

“七幕页面全部打开”仅是活动完成。能力是否得到支持，需看对应任务表现。

## 3. 核心范围：六个产品增量

### E01 学习目标、能力节点与课程路线

**用户故事。** 作为初学者，我希望进入一课前知道学完能完成哪些任务、有哪些必要概念，以便选择合适的课程。

**具体产出。** 为现有概念规范稳定 ID；为 12 课定义少量可检验能力与先修条件；每条目标必须关联至少一个任务和一种产出。先修、强化、对照关系分开，不把所有知识词条都变成先修。现有四条主题路径保留，补上推荐顺序和桥接任务。

**验收。** 任一课的详情、教学目标、练习和笔记能够追踪同一个能力 ID；路径无循环先修；已知概念可通过诊断跳过入门帮助；跳过检查不禁止进入课程；正式案例不能只挂目标而没有对应任务。

### E02 任务与反馈引擎

**用户故事。** 作为正在犯错的学习者，我希望看到针对自己错误的下一步提示，而不是简单得知答案。

**具体产出。** 统一支持选择与理由、数值、排序、对照选择、证据选择、简短解释等任务；使用明确 rubric；保存 attempt、题目版本、内容版本、回答、提示使用、反馈、模型条件和运行引用。首次作答、查看解释后的修订、平行题独立作答必须分开。

**验收。** 预测没有发生前不能反馈运行结论；预测错误允许继续学习；“不知道”是一种有效状态；每个常见误解都有具体练习或查证动作；退架后出现平行题，不能靠重新点击已经显示答案的原题证明独立理解。

### E03 解释笔记与证据工作台

**用户故事。** 作为看懂了图表但还不会解释的学生，我希望系统帮助我把发现整理成一条有根据的经济学解释。

**具体产出。** 基于现有引用建立解释卡：主张、证据、行为机制、集体机制、适用条件、可能的另一解释。相关运行、时点和主体可回查。学生可比较“我原来认为—证据显示—我现在的解释”。知识索引汇聚多课同一能力的卡片。参数台加入“带入解释卡”按钮，原 run/result_hash/经济时点不丢失。

**验收。** 一条主张能链接多条证据，一条证据可支持多个主张；引用有效不自动等于解释正确；数值与事实引用由确定性验证处理；开放文本使用人可理解的 rubric、自评和示例对照。自动反馈须标注建议性质和依据。

### E04 跨案例迁移与复习

**用户故事。** 作为已经完成一课的学生，我希望在另一问题中检验理解，并在忘记前有一次短练习。

**具体产出。** 每条路径有近迁移与跨案例对照任务；每课至少有一项不复述原题的迁移任务。初版复习按透明、可配置日程和最近证据安排，不宣称最佳个体化间隔。先显示问题，再允许查笔记或提示。参考答案查看后需要用新题检验。

**验收。** 学生无需重跑整个案例即可做短复习；题目来源、能力和版本明确；未到期/到期/延后状态可恢复；时区、跨天、内容升级和清除记录不造成假通过。复习不是强制通知，用户可暂停。

### E05 个人学习首页与推荐

**用户故事。** 作为重新打开平台的学生，我希望马上知道继续哪里或练什么，并了解推荐的原因。

**具体产出。** 在现有首页加入学习目标与行动卡：继续、复习、下一课。首访提供“我想理解一个事件 / 跟着路径学 / 自由探索”，可直接忽略并开始拍卖。可选择短练或完整课，所标时长先作为设计预算，之后根据实际试走校准。

**推荐规则。** 优先恢复未完成的核心任务；其次是显式误解练习；再是到期回忆；然后按先修进入下一课。给每项建议一句依据，例如“你已能核对现金守恒，下一步检验净资产与可即时支付现金的区别”。避免只说“为你推荐”。

**验收。** 推荐可从事实记录重建；没有数据时诚实给默认路线；改变目标、跳过任务和关闭复习均可恢复；不以模型生成的学习者性格标签推荐。仅在本机即可工作。

### E06 教学内容运营与轻教师辅助

**用户故事。** 作为内容维护者，我希望新增案例只需要满足明确教学合同，不必另写一套应用；作为教师，我希望快速取用可讨论的机制问题。

**具体产出。** Case Package 增加能力映射、题目与解法、误解条目、提示树、必要/扩展任务、证据选择规则、迁移题、资料摘录与教学暂停点。内容验证器检查引用、目标覆盖、参数支持范围、任务顺序与版本迁移。旧概念词典/教师模式进入新导航，保持同一内容源。

**验收。** 删除一条任务后若造成学习目标无证据则构建失败；陈旧引用给出可定位诊断；一课可导出学生活动页与教师引导页；答案默认隐藏，切换展示模式不丢失学习数据。

## 4. 信息架构与主要页面

主导航继续保持简洁：**开始学习、案例、学习路径、我的学习**。自由实验在次级入口可见；教师辅助进入每课更多选项。对旧路由做兼容，不要求为改名打断链接。

### 首页

- 首访：明确一句产品承诺；一个有结果的行动入口；三个可跳过的学习意图；保留精选案例。
- 回访：继续当前任务置顶；一条有原因的复习；一条下一课；下方仍可自由找案例。
- 全部完成：提供迁移挑战、自己的实验和选定的延伸案例，避免“100%后无事可做”。

### 路径页

- 顶部：这条路径要回答的经济问题、最终可展示的能力、所需基础。
- 主体：有顺序的 3–4 个学习节点与桥接任务，显示已进行活动与能力证据两类状态。
- 展开：概念关系图、替代入口、正式理论与延伸阅读。
- 默认不展示巨型图谱，避免先让学生理解平台的知识工程。

### 案例详情

- 第一屏：真实/实验/理论身份、引入问题、学完能做的两三件事、预计活动、进入/继续。
- 第二层：先修自查、不同角色、会操作的变量、将完成的作品。
- 进一步展开：史料来源、理论出处、模型简化与数据身份。事实边界持续可见。

### 学习页

- 保留场景叙事与领域面板，当前任务为视觉中心；默认同一时刻只有一个主要提交动作。
- 边栏或下层：相关概念、我的预测、证据收集、分层提示；需要时展开。
- 每个暂停点形成小循环：预测→观察→查证→解释一句→继续；阶段性总结再串成完整机制链。
- 主结果必须分清个人收益、群体指标和宏观指标，防止“我赚了所以市场有效”等错误联结。

### 我的学习

- 顶部显示正在形成的能力与可执行任务，不做成绩排行榜。
- 三个视图：课程记录、概念与解释卡、复习任务；旧笔记与运行恢复在同一处。
- 每条能力状态可展开证据、题目、提示使用与更新时间；用户可指出自评不一致或重新检验。
- 导出保留可读内容和机器可还原文件，敏感模型设置不进入学习记录。

## 5. 三条端到端产品路线

### 路线 A：价格、价值与交易效率

拍卖入门→学生估计最高可接受报价→参与交易→解释自己是否成交→从私人价值和成本核对剩余→只改变费用，预测并验证→在未见过的小市场中辨别成交价与总剩余→次日回忆“价格不是价值”→柠檬市场对照信息条件。

**作品。** 一张“什么条件下自愿交易形成可实现剩余”的解释卡，含个体证据、市场指标和信息条件边界。

**防误解。** 一次未成交不证明市场无效率；市场价不是所有人的主观价值；拍卖的机制不能直接推断所有现实市场均有效率。

### 路线 B：挤兑与流动性

SVB 历史入口→资产负债表短练→识别储户急用钱与相信他人提款的动机→预测行动→观察网络与提款、现金、出售证券→区分流动性不足与净资产为负→改变一种制度或流动性条件→迁移到“银行有正净资产但今天现金不足”的新题→闪电崩盘对照。

**作品。** 带时点的机制解释：预期与行动怎样改变支付压力，以及哪些结论依赖资产处置折价和制度条件。

**防误解。** 银行存款义务、证券资产和交易所订单簿是不同对象；两案例都可涉及流动性，传导机制不应混同。

### 路线 C：个体激励、合作与制度

公共物品贡献选择→先算私人边际收益与群体收益→观察重复互动→比较一种规则→解释惩罚的收益与成本→公地资源存量迁移→识别公共物品与公共池资源的区别→碳市场理解外部性与制度边界。

**作品。** 一份简短制度建议，含激励变化、集体后果、实施成本和不能由模型证明的部分。

**防误解。** 合作比例上升不自动意味着社会净收益上升；公共物品、公地与碳许可并非同一个博弈。

## 6. 成功指标：依据实际 design-kpis 工作流

### 6.1 目标树

用户目标是建立可迁移的经济机制理解。产品需要支持：**独立完成任务→形成有证据的解释→延迟后仍可使用→在新情境中检验。** 活动完成与回访是过程指标。测试通过和运行成功是服务质量底线。

下列是建议的未来指标定义，所有当前基线均为“尚未采集”。不据此预测学习增益。应先建立任务质量，再测量；一个题库失衡的正确率不会成为可信能力指标。

### 6.2 建议保留的两项主要学习指标

| 指标 | 定义、粒度与分母 | 数据来源与防操纵 | 用于什么决策 |
|---|---|---|---|
| 独立迁移证据达标率 | 单位为本地学习者 × 能力 × 迁移题版本。分母为已进入相应路径结尾且首次提交有效迁移任务的单位；分子为未查看该题提示/答案、按预先公布的 rubric 达标的单位。另报“启动→提交”覆盖率，避免只看提交者 | LearningAttempt、题目版本、提示事件、规则评分或人工/自评类型。开放解释自评与经审阅评分分别列示；不混成一个权威分数；重复题、导入记录、模板答案不算新独立证据 | 哪些课程需要更换任务、补充支架或加强跨案例桥接 |
| 延迟回忆/应用的首次独立表现 | 单位为本地学习者 × 能力 × 复习计划。分母为在定义窗口内实际尝试的到期任务；分子为第一次提交且未用提示时达标。并列报告到期任务的尝试覆盖率和间隔分布 | ReviewSchedule + LearningAttempt；区分规定窗口内、提前、延后；不把未回来的人视为答错，也不能从答题者推广到所有人 | 复习题是否合适、先前解释是否脆弱、下一步应复习还是推进 |

两个指标的分母均有参与选择偏差，界面与报告必须同时呈现覆盖率。它们是学习证据的代理指标，不等于已经证明平台造成学习提升。

### 6.3 驱动指标与运营诊断

- **有效闭环形成率：** 已启动课程会话中，形成预测、有效运行观察、相关引用、解释和迁移尝试的比例。自动规则只能核对结构与引用，不能仅按非空文本判定解释质量。用于找流程断点。
- **有提示到独立解题的转换：** 看过某类提示后，后续平行题的独立表现；不同题目难度与观察窗口必须一致。用于决定支架如何退出。
- **首个学习价值的时间：** 从开始本课到第一次完成“行动—结果—一句机制解释”的活跃时间；同时报告未达到人数和卡点。首次目标可设为设计预算，不能现在宣称已达到多少分钟。
- **有效回访：** 首次形成学习作品后，在定义日期窗内完成复习、迁移或下一课关键任务的本地档案比例。仅打开首页不计。无跨设备标识时必须称“本地档案”，不能声称真实独立人数。

### 6.4 两项发布护栏

1. **证据真实性与数据身份：** 所有正式任务引用可追到授权的可见时点；历史事实、离线规则、预计算和 live 输出标签准确；禁止未来信息泄漏或生成不存在的行动。发布验收采用确定性失败样本，发现严重违规即阻断相关课发布。
2. **自主学习可达性：** 无 API 主流程、键盘、常用窄屏、断线恢复与旧学习记录迁移可完成。生产运行故障率与 API 费用另作工程运营指标，不合并成学习效果分。

### 6.5 暂不设置的数字目标

没有当前真实用户基线，不设置“留存提高 20%”“学习成绩提高 30%”或“全部用户十分钟掌握”。阶段工程验收可设置绝对交付门槛：12 课目标全部关联任务、所有正式课离线闭环、迁移题和误解反馈齐备、关键路线可验证。实际学习指标先采集可解释小样本与题目质量，再讨论改善目标。

## 7. 最小数据模型与迁移原则

学习领域合同以 `education-contracts.md` 和主规划架构附件为唯一工程定义，本产品文件不另造平行 Schema。下表说明统一对象承担的用户价值；字段、校验与版本规则由工程附件维护。

| 统一对象 | 产品责任 |
|---|---|
| ConceptDefinition | 稳定概念身份、关系与解释；支持跨案例索引 |
| LearningOutcome | 可验证的学习结果及其先修条件 |
| AssessmentItem | 有版本的题目、反馈、提示、变体与评价方法 |
| LearningAttempt | 一次不可覆盖的作答、提示暴露与评价证据 |
| LearnerEvidence | 由记录推导的、可解释的能力证据状态 |
| LessonActivity | 七个阶段内的主线与短补救任务 |
| ExplanationCard | 主张、证据、机制和边界组成的学习作品 |
| ExperimentCard | 假设、处理、真实运行结果与限制组成的实验作品 |
| ReviewSchedule | 透明的复习计划与执行状态 |
| Recommendation | 可执行建议及支持它的记录和原因 |

学习意图与可用时间可作为现有本地设置保存，初版不因此再建复杂用户模型。SimulationResult 继续只负责运行事实。

- 首期可复用 localStorage 配置，学习账本是否迁入 IndexedDB 由数据量与导入事务需求决定；不为这些需求增加远程账户系统。
- 原有 run/event/counterfactual 引用不变化，新数据通过 ID 引用它们。
- 旧学习记录迁移为“已活动/原草稿”，能力状态保持未验证。
- 内容版本更新需区分文字修订、任务变更、机制变更；决定是否保留证据、需重答或只是重新核对。
- 为后续跨设备保留可导出 schema，当前不把同步平台作为交付前置。

## 9. 面向 Codex 的产品实施约束

1. 开始任何切片前读当前 HEAD、AGENTS、对应源码和前一阶段验收，先确认已有能力。
2. Skills 动态发现；本轮产品指标确实使用了 `data-analytics:design-kpis`。不能把它扩称全套 PRD、访谈或 UI 设计能力。
3. 每个需求同时给用户故事、界面变化、学习意义、数据合同、失败状态和验证方法。
4. 每个切片交付一条可运行学生路径，随后补文档；不能连续多个工作包只产规划。
5. 修改反馈或任务顺序时不破坏原始预测、可见信息边界、运行身份和证据验证。
6. 活动进度、题目评分、自评、AI 建议、能力状态各自独立；任何转换都有明确规则。
7. 不新增静态演示伪装交互；允许真实预计算回放，标签和支持的参数范围保持准确。
8. 发布前进行内容与产品审查，确认新学生可以解释“为何做这个动作、得到什么、下一步是什么”。


## 10. 首次十分钟体验脚本（设计预算，待试走校准）

默认仍使用已经成熟的拍卖入口。十分钟是本轮要验证的体验预算，不是已测得的学生完成时间，也不要求所有学习者按钟表推进。

| 时间预算 | 学生实际做什么 | 看到什么 | 本轮新增的教学价值 |
|---|---|---|---|
| 0–1 分钟 | 阅读一个问题，可直接选择“开始”；不强制注册或填资料 | “你愿意最多付多少？成交价格和你获得的收益一样吗？” | 进入前就知道要学会区分价格、价值与剩余 |
| 1–3 分钟 | 领取买家身份，选预测，填写最高可接受支出 | 私人价值、现金、可买数量；可选“不确定” | 首次回答落入学习证据记录，指出需要帮助的具体概念 |
| 3–5 分钟 | 报价，推进到自己的首次相关事件；若未成交则观察当时可见原因 | 订单、对手、成交或未成交、本人现金与物品 | 在真实事件中建立“自己的选择→实际结果”，不先等全市场闭市 |
| 5–7 分钟 | 核对本人剩余，选择一条支持解释的原事件 | 小型算式、证据高亮，答错后分层提示 | 反馈指出是价格/价值混淆、算术还是证据选择问题 |
| 7–9 分钟 | 改变一个必要条件，例如费用，先预测再比较 | 同一经济时点的实际对照；已有参数台能力复用 | 形成可检验解释，不为了完成进度强跑所有预设 |
| 9–10 分钟 | 填一张短解释卡，再答一个未见过的平行小题 | “我现在能解释什么 / 哪一处还需练 / 下次做什么” | 收获可保留的作品与下一步；未达标也有明确补救路线 |

Schelling 与 SVB 后续采用相同的学习节奏，领域任务保持不同：Schelling 在局部九格判断和全局分化间建立关系；SVB 在储户决策、银行现金和净资产之间做区别。

核心路径只要求与目标直接相关的任务。第二个制度对照、五种子实验、模型接口和自由实验均可保留为扩展；完成必要任务后提供明确邀请，不抢占首次主线。

下表用于产品排期讨论，已与主规划工作包命名对齐。人日表示具备相应能力的人投入一天，不等于 AI 运行日或自然日。基线是当前 UP00–UP11 已合并，不重复计算既有首页、场景、参数台。

内容作者/经济学审核不能视为免费输入。如果 ED08 承担新写全部九课的平行题、迁移题、详细解法和逐条资料复核，额外准备约 6–10 内容人日；这笔内容投入单列，25% 风险储备另外计算，不把兼职审核当作零成本。两位工程成员加兼职经济学审核约 6–9 周、单人约 12–16 周只是依赖这些前提的计划区间，排期前应先用三旗舰实际吞吐量重新估计。
