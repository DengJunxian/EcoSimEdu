# UP10 多角色模型实验

2026-11-17。工作树基于 `585ffcbaaeb292f0addc10331ae7dae0c57ebd84`。本地执行、合同和规则参考已通过，实际供应商验收待验证。

## Skills A–E

- **A Discovery**。复核 HEAD、AGENTS.md、工作树、宿主 OpenAI Docs 和 Playwright 指令，读取升级包 UP10、Live 规格、原 Live v1 回执和预算代码。定位四门课既有的观察生成、行动合法域及统一结算函数。
- **B Selection**。沿用已有工具禁用的供应商 transport 与离线领域引擎，按 OpenAI 结构化输出文档约束动作，使用本地注入 transport 复现预算、乱序与失败路径。浏览器验证独立运行入口、对照及下载。 [结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)
- **C Execution**。给四个内核加入冻结观察、合法动作、分步原子提交回调。SQLite 保留每个经济时点的事件和帧、去重提交指纹、保守费用预留及实际用量回执。课堂现有运行和 L1 入口继续使用原合同。
- **D Collaboration**。机制负责人独立检查原规则和旧哈希。集成负责人实现 SQLite 执行、测试与页面。导师负责人核对不同调用入口共用的累计费用上限，验收负责人把多角色记录加入独立备份复原。
- **E Validation**。四课在注入 transport 中均有至少三个角色、三个经济时点的合法模型动作入账。合同覆盖同轮冻结、返回乱序、非法行动后重试及回退、重复提交、预算不足、用量未知、暂停继续、取消与重启。Chrome 逐课走过规则、对照和导出。 [合同](../../tests/contracts/test_l2_execution.py) [机制](../../tests/mechanisms/test_live_l2_domains.py) [浏览器](../../tests/e2e/test_multi_role_lab.py)

## 运行

`/experiments/multi-role` 可选择四课的学生动作并离线运行同条件规则参考。多角色实验启用后，学生在服务器上限内选限额并确认本次调用。四课计划机会分别为公共品 18、SVB 30、信息级联 3、GameStop 3。公共品参考使用六轮，SVB 保留 60 位储户及原请求与实付语义，级联先声明政策后代入唯一私信号，GameStop 沿用原订单簿。

状态页区分模型与规则决策，列出实际覆盖、缓存和用量、预算回执及停止原因。取消时提交前缀保留，当步未提交的模型动作不进入经济结果，已发生的费用仍留在账本。导出包含对应规则参考和事件。进程重启可读已提交前缀，执行保持中断状态。 [执行器](../../services/simulation/live_l2.py) [操作说明](../../user-guide.md) [服务端配置](../../developer-guide.md)

实际供应商的四课端到端、无回退合法样例及账单核对仍在验收范围。真实模型请求本轮为零。跨进程继续计算属于另一个需完整检查点的阶段。
