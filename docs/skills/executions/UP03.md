# UP03 首课工作台执行记录

- **A · 发现**。核对实际架构、数据质量、前端和浏览器技能，读取当前回放、运行、订单、账户及配对时钟代码。
- **B · 选择**。应用 codebase-design 1.3.2 的小接口与集中数据关联，在原运行存储之上提供拍卖课堂读取接口。用 analyze-data-quality 1.2.0 检查粒度、订单 ID 连接与缺值。交互采用 Impeccable 4.8.0 的 Operate 方法和 Playwright。
- **C · 执行**。一次运行内按事件定位订单与账本，比较按轮末或各自收盘对齐。价格点关联两张相同运行的原始订单与先到订单，选择一方可读其账户结算差额。引导读取事件前缀，复盘主动揭示全程。 [课堂投影](../../../services/simulation/auction_view.py) [共享选择](../../../student-web/src/cases/auction/selection-context.tsx) [交易大厅](../../../student-web/src/cases/auction/market-floor.tsx)
- **D · 交接**。UP00 提供 SVB 和旧课堂的回放行为底线，UP02 提供场景与选择器。UP03 保持运行 API 和存储格式，UP04 使用同一个播放器、游标、固定主体和证据查询。独立走查核对了同一价格点上的买卖单、原始订单定位，以及选中与固定分离。
- **E · 验证**。Chrome 按 320、390、768、1440 像素走拍卖运行，SVG 价格点和价格表支持键盘操作。HTTP 回归验证开场只含市场开盘，复盘可展开并核对收益、两张订单及双方前后账户。真实浏览器确认 96 成交和 1 未成交两条路径。 [性能与复跑](../../upgrade/progress.md)

拍卖账户由现有完整快照直接读取。SVB 请求—支付和 Schelling 居民重投影属于后续旗舰领域适配，当前继续走通用回放。引导范围属于课堂呈现和请求合同，旧版复盘与原始事件端点支持完整记录。
