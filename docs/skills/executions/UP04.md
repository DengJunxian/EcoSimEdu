# UP04 双向拍卖执行记录

- **A · 发现**。复核拍卖旗舰规格、模型与预计算覆盖，确认本机 Impeccable、Playwright、数据质量方法可用。
- **B · 选择**。从三项任务组织课堂：交出一单、用账本复算、固定报价比较制度。采用 UP02 的选择—反馈—证据映射，不确定预测和收盘未成交各有可操作分支。
- **C · 执行**。新版课堂包含七场景。报价后按需逐事件推进，从成交点打开真实双订单和账户。在解释场景计算买卖剩余与平台费。两项对照复用原种子、原报价，按同轮末或收盘同步，支持核对收费成交。笔记保存原预测、事件与对照、条件和自评，可导出 Markdown 与 JSON。 [新版课堂](../../../student-web/src/cases/auction/auction-lesson.tsx)
- **D · 交接**。内容与运行契约分别版本化。独立成员用原始机制、固定种子和独立数据库复走两条报价路径。UP05/UP06 可复用场景合同和时间语义，领域状态查询按各自机制实现。
- **E · 验证**。种子 1962、报价 96 的基准、需求、收费的结果哈希匹配既有预计算，成交量为 6、7、4，含平台总剩余为 180、272、137 代币。收费场平台收入 48。报价 1 时 B01 的订单在收盘撤销，市场仍有 4 笔其他成交。测试也覆盖非法报价、收费导致拒单、固定回放 96、当期结算对账、伪造证据、刷新以及新旧深链。 [浏览器复跑](../../../tests/e2e/test_auction_scenes.py) [运行契约复跑](../../../tests/contracts/test_auction_classroom.py)

学生提交一次开局限价，四轮自动交易由原有规则推进。课堂体验实测采用本地 Chrome 与独立 SQLite，正式课堂效果和真实供应商运行属于其他验收。
