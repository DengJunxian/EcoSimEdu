# 工作包执行约定

发现宿主已暴露、实际可读的 Skills。按工作包选择与输入、输出和验证直接相关的方法。检查实际路径和版本，依据本地数据、代码和工具执行。范围、经济条件、数据身份和验收项以项目文档为准。

先明确契约，再接上调用方。工作包交接顺序为 WP00→WP01→WP02→WP03/04A→WP05。内容定义先供撮合和 UI 读取，后由真实浏览器联验。单独记录走查发现、修复、检查结果和能力边界。执行记录位于 executions/。

## 新轮工作包

每个 UP 工作包在同一张交付链执行 A–E。A 核对宿主实有入口，B 按当期风险挑选并读完相关说明，C 用方法改动产品或实测证据，D 明确实现、数据、独立验证的交接，E 在真实运行与浏览器核对结果并登记范围。主分支保留历史 WP 和 RC 记录。UP00–UP11 的实际交付统一跟踪于[升级状态](../upgrade/progress.md)，所用方法及执行回执见[工作包索引](skills-application-matrix.md)。
