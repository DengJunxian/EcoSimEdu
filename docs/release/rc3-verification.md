# 1.0.0-rc.3 逐事件查阅验收

RC2 的时间轴按快照定位。RC3 增加独立事件入口，支持同一快照关联多条事件，以及可以读取但没有关联快照的事件。十二课的生成结果、历史运行哈希、笔记和既有 `tick` 链接继续沿用。

| 行为 | 验证 |
|---|---|
| 从快照转到事件 | 在已保存的运行页选择「按事件序号查看」。双向拍卖预计算回放用实际浏览器验证已有快照链接、跳转、上一条和返回关联快照。 |
| 用事件序号定位 | 输入从 0 开始的事件序号，或打开带 `case`、`run` 和 `event` 的链接。事件页展示原始字段，可前后移动。 |
| 事件位置与快照分开 | `GET /api/runs/{key}/events/{seq}` 返回原始事件、总数、运行结果哈希和可空的关联快照序号。关联快照表示所在帧；快照仍由既有 API 提供。 |
| 边界、篡改与兼容性 | 契约覆盖同帧多个事件、无可用快照、负数与越界序号。缓存命中后修改数据库字节，下一次查询仍返回校验失败。其余十一课分别核对新 API 与旧 trace 返回的序号 1 事件完全一致。 |
| 新页面检查 | Chrome 390px 与 1440px，打开原始字段和错误状态，共 6 个 axe 扫描状态，未报告违规或页面横向溢出。[扫描结果](rc3-event-accessibility.json) |

只读事件查询复用已有的运行哈希校验。重复访问时，最多缓存一份按数据库原始字节匹配的已校验事件索引，入缓存的原始记录上限为 24 MiB。首次访问或超出上限时直接解码并校验。索引只保留事件与关联帧序号，快照内容仍从持久化运行读取。

## 组合规模与回归

同一合成样本含 500 主体 × 300 帧、10 万条事件，单帧 5,000 条关系。API 与 Chrome 直接链接各抽查均匀分布的 30 个序号，包含 0 和 99,999。浏览器未发起整份运行请求。首轮浏览器 p95 为 211.042 ms。优化后，同一运行的浏览器整页直达 p95 为 41.067 ms，事件 API p95 为 6.384 ms。首次 API 读取单次 144.772 ms，返回单事件的测试响应最多 318 bytes。测试覆盖首尾、范围错误和分布抽样。[性能收据](rc3-performance.json)

```sh
.venv/bin/python -m scripts.benchmark_student_lab --combined
.venv/bin/python -m pytest -q tests/contracts tests/mechanisms tests/e2e
```

macOS 从空目录解包安装锁定依赖后，227 项契约、机制与浏览器测试通过，复算 12 课的 41 条固定轨迹。[安装收据](rc3-install.json)

关闭模型服务后，以复制的数据库打开 4 条已有真实模型事件并回到各自快照，运行哈希匹配，供应商尝试记录保持 8 条。[历史回放收据](rc3-saved-events.json)

继续使用已读 Impeccable 和 Playwright 的控件与浏览器走查方法。报告与已知范围沿用两份已读 anti-defensive-writing 的写法，区分快照、样本和原始事件。原 RC2 的 [跨平台与可访问性验收](rc2-verification.md)保留为该版本证据。
