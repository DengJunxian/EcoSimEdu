# 1.0.0-rc.5 大运行首次读取验收

[RC4](rc4-verification.md) 的大运行首次事件读取实测 252.601 ms。RC5 在新写入的大运行中保存已有哈希所使用的规范 JSON 字节。首次读取由 SHA-256 直接核对这些字节，再用 SQLite 提取单条事件或快照。这减少了完整 JSON 解码及重序列化。运行结果哈希算法、公开 JSON 契约和历史链接继续沿用。

新运行仅在常规序列化会超过 24 MiB 时采用规范格式。小运行保持原有字段顺序。旧格式立即可读，首次读取仍走解码校验。实际本机数据库有 8 条已保存运行，最大 1,380,837 bytes，本轮没有重写历史库。规范存储标记不出现在 API 结果中。

## 性能

同一合成数据含 10 万条事件、500 个主体 × 300 帧、单帧 5,000 条关系。RC5 规范存储大小 34,743,930 bytes（约 33.1 MiB）。测量在 Mac17,3、macOS 27.0 ARM64 和 Chrome 157.0.8103.78 完成。

两份运行有相同结果哈希，只有存储元数据不同。冷读组交替访问两份记录，每次错开进程内上一次校验的指纹。API 和浏览器各项测量 30 次，覆盖序号 0 至 99,999 的分布抽样。冷读的界定是本机服务的校验缓存未命中。

| 操作 | 缓存未命中 p50 | 缓存未命中 p95 | 同一运行重复请求 p95 |
|---|---:|---:|---:|
| 单事件 API | 59.165 ms | 66.449 ms | 53.620 ms |
| 快照 API | 45.048 ms | 47.692 ms | 35.484 ms |
| Chrome 事件直达 | 94.513 ms | 98.951 ms | 104.199 ms |

新格式首次单次 API 请求实测 86.734 ms。组合样本的浏览器从事件链接读取单条记录，响应正文最大 533 bytes。样本覆盖首次定位与重复定位，范围是本机串行访问。[性能收据](rc5-performance.json)

## 契约与复跑

- 序号越界与缺失关联快照返回预期状态。旧格式的大运行、小运行、新规范格式的大运行分别通过契约。数据库改动后，两种按记录读取的 API 都重新验证并返回哈希错误。
- 规则、预计算和真实模型使用同一持久化函数。旧回执的事件与快照可继续读取。源课程数据通过固定轨迹检查。
