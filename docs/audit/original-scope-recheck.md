## 后续按验收影响推进

1. **案例边界和资产登记（WP02 → WP06 → WP10）。** 先从双向拍卖的“无供需交叠”开始，使用现有订单簿真实生成零成交轨迹。保留基准与两组必做对照，将边界设为可选学习实验。再逐课用已有测试或最小参数验证边界，明确可比条件、缺失指标和引用路径。验收要求是十二课各一条学生能启动、查看证据与导出结果的边界路径。随后补可核查的来源定位、版本、生成或取得状态和许可边界。
2. **运行状态与增量（WP04 → WP07 → WP10）。** 先选一个长规则案例形成执行层验证：原子边界、持久化进度、暂停和继续、进程中断、`after_seq` 游标。再接入快照加增量，分别核对任意快照恢复所得状态、重复提交防护、取消保留内容、旧运行读兼容和新旧性能。Live 仍采用四课小范围授权验证，传输或调度测试先走受控供应商。
3. **发布复验（WP09 → WP10）。** 用固定 100×100 规则用例测时，补人工对比度、表格、焦点和被 axe 标出的目标尺寸。可获得原生宿主时补 VoiceOver、NVDA 和 Windows。仅在新平台、合并或公开部署的确属于交付目标时纳入相应签收；当前用户要求为本地实现与复核。
4. **范围扩展。** 正式课堂效果验证在原交付包 PRD 中列为本期之外，需要实际课程部署与参与者流程。跨供应商实调、更宽多角色和多轮也是独立扩展；本期的四门真实 API 案例已经单独验收。

本轮应用已有的 Playwright 交互验证和两份 anti-defensive-writing 证据写作方法。复核避免把附件中的产品判断当作功能实测；规划的下一项仍保留为计划，直到具体产出与实测收据就绪。
