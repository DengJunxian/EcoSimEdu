# WP05 · 硅谷银行挤兑的暂缓提款分支

2026-11-20。沿用居住隔离已经验证的检查点、预测、分支身份和续学方式。在八阶段课堂的「机制与涌现」打开「暂缓一次防御性提款」。到达可操作的轮末后，预测下一轮末待付的方向，再让 D01 暂缓一次防御性提款。

## 决策和恢复

检查点由原规则决定。当下一轮 D01 会首次申请防御性提款时，课堂允许学生选择暂缓一轮。到期工资款和已经入队的申请按原条件处理。再下一轮重新按可支配的未保障余额、邻居消息及公开信号判断。

浏览器从轮末恢复储户存款、待付和累计实付、既有防御性提款记录、FIFO 队列、首次申请信号和银行资产负债数据。分支保留此前的帧和消息，记录当轮额外行动，然后复用原引擎完成其余轮次。主回放保留原来的揭示上限。Python 在同一组初态上独立重放，在指定轮次执行同一动作，用于交叉核对。

可以逐轮查看累计申请、累计实付、待付、现金和权益，回查 D01、急售与支持借款的原流水。原续学检查点保存最近一组分支及预测。证据导出包含两个运行编号、结果摘要、原始流水和消息来源。

## 课堂样例

第 1 轮申请工资款的默认课堂种子中，第 2 轮末已有 107 单位待付，银行现金为 0，D01 下一轮可申请 17 单位防御性提款。以下是两组使用相同种子、相同工资款时点和同一队列规则的结果。

| 指标 | 基线 | 暂缓分支 |
| --- | ---: | ---: |
| 第 3 轮末累计申请 | 1,278 | 1,261 |
| 第 3 轮末累计实付 | 540 | 540 |
| 第 3 轮末待付 | 738 | 721 |
| 第 20 轮末待付 | 257 | 257 |

分支第 3 轮的事件 3/1 记录 D01 暂缓提款，当时没有现金和负债分录。第 4 轮重新判断后，D01 申请 17 单位。期末两组待付相同。
