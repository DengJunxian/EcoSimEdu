# 四阶段课堂迁移与验收

迁移以一门课为一轮验收。先从 `cases/<case_id>/case.json`、`lesson-v2.json`、`model.md` 和原内核运行确定角色、合法行动、来源、原始事件及政策条件。历史材料、教学设定、运行结果和解释假设分别标注。保留现有学生端的链接、运行身份和学习记录。

## 每门课填写

| 字段 | 交付要求 |
| --- | --- |
| 课程身份 | 案例 ID、内容版本、真实资料、教学初始配置、浏览器内核版本。固定种子资产可复核来源，只携带输入。 |
| 第一阶段 | 一位可辨认的角色、当下可知的信息、2–3 个简短决定与作答后反馈。第一题之前显示需要使用的数字或信号。 |
| 第二阶段 | 真实参与者视图、状态、约束、局部信号和行动理由。单步前后使用同一参与者 ID。大群体可分页，每页最多 30 位，汇总仍使用完整群体。课堂规模不足 20 时，先审查能否用同一规则构造并验证更大的教学种群。 |
| 第三阶段 | 选一个主指标及单位，明确第一处值得暂停的时点。用当轮真实事件核对净变动。若下一轮规则读取了群体状态，用 `priorSignal` 指回该帧，并区分进入决策规则与实际上改变动作。资料对反馈机制的解释另有标识。 |
| 第四阶段 | 挑一项原案例允许的干预，记录共同的种子、角色决定、种群与其余参数。先选预测，再运行。展示对齐刻度、结果差异和适用条件。 |
| 证据与验收 | 独立复算边界情形、对照原内核、完成键盘和窄屏的课堂走查。记录到秒或轮的来源，确认数据与学习身份不会被覆盖。 |

## 接入并验证

1. 实现 `Lesson` 和纯函数 `run({ seed, choices, policy })`。每轮从 0 连续编号，保留稳定个体 ID，分离每项真实事件及其指标贡献。用 `Frame.metrics` 的 `null` 表示未定义值，例如未成交时的成交价。折线留空，表格显示「未定义」。预测题选用可比较的指标。
2. 复用 [Studio](src/Studio.tsx)、[个体透视](src/visuals.tsx)和[反事实对照](src/Counterfactual.tsx)。对照组保持与基线相同的个体顺序和随机输入。角色局部信号保留源事件 ID。需要学科特定的反馈时，可参照 [SVB 的复核卡](src/SvbReview.tsx) 注入一块视图。
3. 用 [公共契约检查](tests/lesson-contract.mjs) 验证可复现性、种子、参与者、逐轮增量、历史信号和配对结果。用现有 [两个适配器的调用样例](tests/curriculum.test.mjs) 作为测试模板。按学科再核对必要的守恒、因果证据和极端结果。新模型与原模型口径不同的地方单独记录。
4. 通过桌面与手机宽度的键盘走查后，将可加载的课堂模块登记到 [课堂注册表](src/classroom-routes.ts)。学习地图会使用同一注册表指向新版课堂，并提供原课堂及进度入口。进行中的迁移保留原课堂链接。

## 十二课迁移结果

双向拍卖、SVB 与表中的十门课均通过浏览器入口。课程 ID、种子和合法行动来自现有案例。两组结果使用相同固定种子，每课一次只改动表中的政策。保留原服务的更多预设和全部旧学习数据。

| 课程 | 原运行证据 | 浏览器政策对照 |
| --- | --- | --- |
| 学校匹配 | 提交、排序、拒绝、最终分配和阻挡对 | 延迟接受与即时接受 |
| 柠檬市场 | 暂定报价、愿售集合、退出及结算 | 混合池与付费质量核验 |
| 信息级联 | 私信号、策略、选择和公开后验 | 公布及隐藏前序行动 |
| 居住隔离 | 实际迁出、迁入、受影响住户的前后邻居数、已揭示区间查找 | 30% 与 50% 的阈值 |
| 公共品博弈 | 同时贡献、公共回报、惩罚扣损和净收益 | 无惩罚与低成本惩罚 |
| 公地治理 | 计划、获准取用、实际取用、剩余量和自然再生 | 开放取用与统一限额 |
| 碳配额市场 | 减排、许可编号发行及转移、交易付款和缴回 | 88 张与 56 张总量 |
| 啤酒游戏 | 下单、发货和到货时钟、四个环节的库存与积压 | 局部需求与全链共享终端需求 |
| GameStop | 同源消息转发、限价撮合、借券担保、回补与交还 | 消息进入或不进入关注账户的下单 |
| 闪电崩盘 | 计划释放、实际成交、库存阈值和剩余挂单撤回 | 库存触发撤单与持续报价 |

四人、四级供应链、八家企业及十二人等固定结构沿用原案例人数。Schelling 对 340 人完整开局实时演算，提供社区位置图与按编号选人。每门课的对照选用同一经济时点或同一流程阶段。没有对应帧时保留缺值。
